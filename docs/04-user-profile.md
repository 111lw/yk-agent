# 04 用户画像系统

> 画像是个性化推荐的核心资产。目标：**每次推荐都能说清"为什么推荐给你"，且系统越用越懂用户。**

## 三层画像模型

| 层 | 内容 | 来源 | 存储 |
|---|---|---|---|
| L1 静态人格 | 旅行人格类型（见下）、性格倾向（Big Five 简化） | 冷启动引导对话 | `user_profiles`（结构化） |
| L2 动态偏好 | 预算区间、节奏偏好、住宿标准、饮食禁忌、出行方式、同行人 | 每轮对话实时抽取 | `user_preferences`（结构化+向量） |
| L3 行为反馈 | 收藏/采纳/拒绝/修改的攻略及具体修改点 | 交互行为 | `feedback_events` |

### 旅行人格类型（L1 枚举，MVP 用 8 类）

`探险型` `度假躺平型` `文化历史型` `美食型` `亲子型` `社交型` `自然风光型` `都市潮流型`

> 用户可复合（最多 2 主类型）。人格类型只影响**表述风格与候选倾向**，不作为硬过滤——数据不足时禁止武断贴标签。

### 动态偏好 schema（L2）

```jsonc
{
  "dimension": "pace",          // 枚举: pace 节奏 / budget 预算 / stay 住宿 / food 饮食 /
                                //       transport 交通 / interest 兴趣点 / companion 同行人
  "value": "slow",              // 规范化值（各维度有自己的枚举/区间，见 code 内定义）
  "sentiment": "dislike",       // like / dislike / neutral
  "weight": -0.8,               // 强度 -1.0 ~ 1.0
  "source": "chat:msg-123",     // 证据来源，可追溯
  "expires_at": null            // 如"十一期间"这类时点性偏好需带过期
}
```

**"我不喜欢爬山" → `{dimension: interest, value: hiking, sentiment: dislike, weight: -0.8}`。**

## 偏好抽取器（profile/extractor.py）

- 独立的轻量 LLM 调用（json_mode），输入 = 本轮对话 + 现有画像摘要，输出 = 偏好增量列表（可空）。
- **幂等合并规则**：同 dimension+value 再次出现 → 更新 weight（累加并截断到 ±1.0）、刷新 source；矛盾值（先说想吃辣后说不吃辣）→ 以新值覆盖，weight 减半再累加。
- 抽取失败不影响主流程（降级为不更新画像），但记日志。

## 画像生效的双通道

1. **生成通道**：Orchestrator 生成攻略时，画像摘要（L1 人格 + top-N 权重偏好）注入 system prompt。
2. **检索通道**：知识库检索与 POI 候选过滤时，dislike 项作为**硬过滤**，like 项作为**加权排序**（weight × 相似度）。
3. **可解释性**：最终回答中引用画像依据（"因为你上次提到不喜欢太赶的节奏…"），依据必须来自真实画像记录，禁止编造。

## 冷启动流程

- 首次对话触发 `cold-start-questionnaire` skill：3~5 轮引导式提问（目的地想法 → 节奏 → 预算 → 同行人），每轮回答即时进抽取器。
- 用户跳过问卷不阻塞，走"从首次攻略请求中边用边学"。
- MVP 简化：问卷可一次性在单轮内完成（前端表单可选接入）。

## 反馈回写（L3）

| 用户行为 | 回写动作 |
|---|---|
| 采纳攻略 / 表达满意 | 方案中涉及的偏好 weight +0.1 |
| 修改攻略某项 | 抽取器处理修改意图（负向信号） |
| 明确拒绝/换掉某 POI | 对应 POI 特征打 dislike，weight -0.5 |
| 停留时长/追问细节 | 记录行为日志，V2 用于隐式偏好建模 |

## 记忆分层

| 层 | 内容 | 生命周期 |
|---|---|---|
| 会话记忆 | 当前对话消息 | 会话内（Redis） |
| 长期偏好 | L1/L2/L3 画像 | 永久（PG），weight 随时间衰减（半年未验证的偏好 -20%） |
| 攻略记忆 | 历史生成过的攻略摘要 + 用户反馈 | 永久（PG），规划同目的地时召回 |

## 模块划分（profile/）

```
profile/
├── models.py        # 画像相关 pydantic model（UserProfile/Preference/...）
├── extractor.py     # 偏好抽取器（LLM 调用，json_mode）
├── merger.py        # 增量合并规则（幂等/矛盾/截断；时间衰减属 V2）
├── summarizer.py    # 画像摘要生成（注入 prompt 用，控制 token 预算）
└── repository.py    # 画像读写：接口 + InMemory 实现（PG 实现随存储接线步骤落地）
```
