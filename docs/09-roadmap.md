# 09 路线图

> 每个阶段有明确验收标准；实现严格按阶段推进，不提前做后续阶段的事。

## MVP：跑通「对话 → 画像 → 自主编排 → 出攻略」（目标 3~4 周）

**范围**：

1. 项目骨架 + 配置 + LLM provider 抽象（方舟/豆包）
2. 核心编排：Orchestrator（Plan-and-Execute）+ Blackboard + 护栏 + Critic
3. 子智能体 ×3：poi-agent / route-agent / budget-agent（经 Registry 注册）
4. 画像：冷启动问卷 skill + 偏好抽取回写 + 画像摘要注入 + L3 反馈回写
5. 工具：map-mcp（geocode/poi_search/route_plan）+ kb_search（最小知识库：精选 20~50 篇目的地内容）
6. 存储：SQLite 全量持久化（画像/会话/攻略/trace，ADR-002）
7. API：`POST /api/chat`（SSE 全事件协议）+ trips/feedback/profile 接口

**验收标准**（对应 01 文档成功指标）：

- [ ] 端到端「对话 → 出攻略」成功率 ≥ 90%
- [ ] 生成的攻略包含逐日行程、预算表、个性化理由（引用真实画像记录）
- [ ] 用户说"第三天太赶了"能触发局部重排且修改点回写偏好
- [ ] 护栏生效：注入诱导长循环的任务，步数 ≤15 强制收敛；副作用动作出现 confirmation_request
- [ ] trace 完整：任一次对话可在 agent_traces 中还原全部派发过程
- [ ] 单测覆盖：画像合并规则、护栏、各子智能体 schema 校验、SSE 事件序列

## V2：数据与体验增强（MVP 验收通过后）

- weather-mcp 接入，天气驱动计划修订（自主编排的价值放大器）
- 知识库扩容与清洗管线；嵌入维度/检索策略调优
- 攻略对比模式（双人格出两版，选择反哺画像）
- 用户登录体系 + 会话跨端
- Alembic 迁移引入（第一个改表需求出现时）
- 评测集建设：固定 50 个画像×请求组合做回归评测

## V3：开放生态（按产品数据决定）

- Skill / Plugin 开放机制（第三方 manifest + 沙箱）
- 子智能体以 MCP tool 形式对外暴露
- 多模态：拍图识景点、行程地图可视化
- 多智能体协作深化（预订 agent 等，仍遵守副作用确认规则）

## 技术债登记处

- MVP 期允许的简化：单机部署、无登录、无监控告警（仅 trace + 日志）→ V2 清理
- `docs/` 与实现不一致处视为 bug，发现即修
